## What changed

3.9.54 fixes the session log a reload leaves behind. Nothing about fishing, the planner or the
press gate changed.

### A reload row carries the session it ended

Rows posted after a reload reported `catches 0` and a `started_at` a fraction of a second before
they were written. The heartbeat did not record the catch count, `checkInterrupted()` posted a
literal `0`, and `postSessionRow()` fell back to `Date.now()` because mount has no
`state.startedAt` yet. The heartbeat now stores `catches`, and the reload path passes it together
with the recorded start.

### The row is filed on the day it began

`fishserve` buckets a row on `localDay(started_at)`, so an honest start is what keeps an overnight
record out of today's total. The reload path needs no day check of its own: the old 110 minute row
looked like a today row because its start had been faked to "now".

### An inlined install reads its own rows back

`loadToday()` returned on `!BASE`, which is always null in a userscript, so the panel posted
session rows to fishserve and never read them. It now uses `BASE || captureServer()` - the same
fallback `postSessionRow()` uses - and the capture address is resolved before the first read, since
`captureServer()` reads a variable mount used to assign after the read.

## Measured

Live in BrowserOS neo on 2026-11-21 (`app.lofi.town`, 1179x886, profile `nepchur`): the panel read
`today 5.4 min` while fishserve held 115 minutes for the same profile and day - two reload rows of
110 and 5 minutes, both `catches 0`, both with `started_at` within a second of their `time`.
