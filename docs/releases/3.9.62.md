## What changed

3.9.62 is the combined release for 3.9.57-3.9.62. Every build was made on the behavior-review
branch; none of the intermediate versions was tagged. No default fishing behavior changed:
**Fast first press** is opt-in and **stallDialMs** is off by default. The rest is panel
diagnosis, pause explanation and core recovery.

### Fast first press (3.9.57)

`fastFirstPress` bypasses the first-press stable-fit hold only on dials narrower than 60 deg or
spinning at 300 deg/s or faster. The crossing planner and every later press are unchanged. It is
off by default (`fastFirstPress:false`) and the panel keeps an amber warning beside it: tapping
the first pass is faster, but a hard fish the hold would have waited for can be missed.

Live A/B on 2026-11-24: default 22 dials / 0 misses / 6 first-press holds in 8m17s; fast 22
dials / 0 misses / 0 holds in 8m31s. The matched 5m07s cut was 9 dials (2 held) against 12
dials (0 held). The fast arm caught 16/16 attempts against 7/9 in the default arm, but the
default arm includes an unseated pause and the sample is too small for an accuracy claim. The
default stable-fit hold remains the conservative choice.

### The panel says why it paused (3.9.58)

Every pause path now records `pausedAt`, and the banner reads
`paused HH:MM · <reason> · <next step>` from one reason map: you paused it, the tab was hidden,
the character was standing, a focus session is running, nothing bit for 10 minutes, the cast
never landed, a nearby player blocked the spot, a player profile was open, or the game is
waiting for a fishing result. Resume also resets `lastCatchAt`, so a run resumed after a long
hold no longer re-pauses as `no-catch` within a second.

### Stuck narrow rings can be named (3.9.59)

The 2026-11-24 ledger put all 167 narrow first-dial misses and 245 of 282 narrow ghosts in
3.9.55's stuck result sessions: rings held 10-13 s after a press the game never settled, while
3.9.56/3.9.57 had none in 1,277 narrow dials. `stallDialMs` (default 0, off) names a held narrow
ring `stalled` instead of scoring it as a timing miss or a ghost. Replaying the overnight ledger
(548 runs, 11,891 narrow first dials) at 9000 ms relabelled 122 of 167 narrow misses (73%) and
166 of 282 narrow ghosts (59%), with zero of 14,753 narrow hits. If it is ever enabled, 7900 ms
is preferred: it catches the whole stuck-ring cluster and leaves the brief fades alone. The
default stays 0 until a live session needs it.

### A stopped core is revived (3.9.60)

Measured live: the panel read `phase: running` while `__fish.status().running` was false and the
clock had stopped. The 1 s tick is the only keep-alive, and a throw before its dispatch was not
recorded. `focusTick()` and `healCapture()` are now guarded separately, failures are recorded
(`__panel.guard()` exposes `tickErrors` / `lastTickError`), and a 5 s watchdog on its own timer
re-enters a silent tick loop. If the phase is running while the core reports stopped, it
restarts the core, counts `zombieRevives`, and says so in the banner. A stopped core also
reports `stalled`, so that stretch is never credited as fishing time.

### The crash-loop breaker (3.9.61)

A watchdog that revives forever hides a game that no longer works. `reviveGate()` allows three
restarts in a rolling ten-minute window; the next stopped core ends the session with reason
`core-crash` instead of starting again. That stop rests like any other, so the next tick cannot
re-enter the loop. The session row carries the guard diagnostics in a new `note` column
(`guard revives=3 windowRevives=3 tickErrors=1 lastError=... doctor=... tickAgoMs=...`), and
fishserve sanitises it to one CSV-safe line. Older five- and six-column files are upgraded in
place and their rows still read back unchanged.

### Blind-game escalation (3.9.62)

`doctor()` has named `detector-blind` after 45 s, but the panel only put it in the phase chip and
a blind run pauses as `cast-stall` at 90 s, so the retry loop hid the condition. 3.9.62 measures
the silence itself: the newer of `sinceBubbleMs` and `sinceDialMs`, or the current core run when
neither has been seen, capped at that run. Once the silence reaches three minutes on a visible
page during a running or cast-stall/no-catch pause, the panel shows a persistent banner:
"detector blind for 3 min - reload the game tab, then sit on a chair by the water". It outranks
the cast-stall retry and log-offline lines but yields to stall, result-missing, seat, focus and
player/profile notices. The state is exposed as `host.dataset.blind` and the style is
`.banner.blind`.

Deliberate hidden, user, seat and focus holds are subtracted from the silence. The reducer
credits a hidden pause it sees; a throttled background tab that never ticked hands its hidden
wall time to the reducer on the browser's visibility return instead. A fresh prompt or dial
clears the pause credit, a watchdog/core restart clears it because the new detector has no
history, and cast-stall/no-catch remain detector failures that still count.

The hidden-return credit was corrected in `fd24e44`: a watchdog revive no longer leaves stale
pause credit that could suppress the warning, and a throttled tab credits its hidden wall time
once rather than twice.
