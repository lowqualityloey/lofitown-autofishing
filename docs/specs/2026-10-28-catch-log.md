# Spec: catch log v1 (server-free telemetry)

Status: approved by the owner (m01668) · Level 2 · 2026-10-28

> Implementation note (2026-10-30): the catalogue was regenerated from a newer game bundle and now
> ships **181 rows**, not the 136 counted at approval time. `tests/catchlog.test.js` pins 181. The
> design, APIs and failure modes below are unchanged.

## Problem

Every catch card is already parsed into `species / rarity / quality / weight / value`
(`autofish.js:630`), but the record only leaves the page when fishserve is running and appends to
`catches.csv`. The one-file userscript therefore keeps **no history at all** after a reload:
no per-species counts, no rarity breakdown, no shiny/event tally, no best weight. The panel shows
four counters.

The card prints a rarity word only for non-common fish, so even the CSV has blank rarity for
commons. The game bundle ships the full species catalogue (136 entries with `rarityTier`,
`minWeight`, `maxWeight`, `baseGold`), which turns that blank into an exact, offline lookup.

## Goals

1. Persist every parsed catch locally, with no server and no extra permissions.
2. Report it per species and per rarity tier, including shiny and seasonal tiers.
3. Keep the oracle honest: a catch exists only when the card text parsed.
4. Cost nothing per frame: the ledger is touched once per catch.

## Non-goals

Cloud sync, multi-profile merge, IndexedDB, a web dashboard, pixel reads, new click paths,
CSV column changes.

## Design

### Embedded catalogue

```js
// <species-catalogue>
const SPECIES = [["Blobfish","Rare",2,20,50], /* ...136 rows... */];
// </species-catalogue>
```

Generated offline by `scripts/gen-catalogue.js` from the saved game bundle
(`shots/diag/c3763.js`, git-ignored). Row = `[name, rarityTier, minWeight, maxWeight, baseGold]`.
The table is data, ~5 KB, and is the only thing that changes when the game adds fish.

### Ledger

```js
{
  v: 1, createdAt, updatedAt, total: 0,
  species: { "Blobfish": { n, best, bestAt, first, last, shiny } },
  rarity:  { Common: 0, Uncommon: 0, Rare: 0, Epic: 0, Legendary: 0,
             Secret: 0, Halloween: 0, Christmas: 0, Shiny: 0 },
  days:    { "2026-10-28": { n: 0, rarity: { ... } } }      // last 60 days
}
```

`rarity` counts tier catches, `Shiny` counts shiny catches (a flag, not a tier), so the tier
counts and the shiny count can overlap - which is what the game actually does.

### Rarity resolution

`rarityOf(rec, catalogue)`:

1. The card printed a rarity word → normalise case (`COMMON` → `Common`) and use it,
   `derived: false`.
2. No printed word → look the species up (stripping a `Shiny` prefix) and use its
   `rarityTier`, `derived: true`.
3. Unknown species with no printed word → `Unknown`, `derived: true`. Never invented.

### API

| Call | Returns |
|---|---|
| `__fish.log()` | `{ total, speciesCount, byRarity: [{rarity, n}], today: {day, n, shiny, golden, byRarity}, shiny, golden, best, last, since, updatedAt, days }` |
| `__fish.logCsv()` | `species,rarity,derived,shiny,count,best_kg,first_seen,last_seen` rows |
| `__fish.logReset()` | clears the ledger, returns `true` |

## Failure modes

| Failure | Handling |
|---|---|
| localStorage full or blocked | write wrapped in `try/catch`, loop continues, one log line at most |
| Corrupt JSON in the key | version + shape validation, silently start an empty ledger |
| Unknown species (game update) | recorded under its raw name, rarity `Unknown`, `derived: true` |
| Weight not parseable | counted, `best` untouched |

## Test plan

Pure helpers extracted by sentinel and run under `node --test`: catalogue integrity (136 rows,
tier counts, unique names), `speciesInfo` (plain/shiny/unknown/case), `rarityOf` (printed vs
derived vs unknown), `parseWeightKg` (kg/g/t/blank), `addToLog` (counts, best weight, day bucket,
tallies), `logSummary` ordering, `logCsv` shape and escaping, `trimLog` retention, JSON round-trip.
Panel test asserts the strip is built and render reads `fish().log()`.
